## Ce qui a bien fonctionné

- **Lots par frontières, pas par fichier** : commencer par les contrats (types racine, apiClient, localStorage, socket, payloads LLM communs dans `services/llm/providerApi.types.ts`) a fait tomber des pans entiers ensuite. Le découpage lots décroissants (gros fichiers de tests à la fin, 1–3 sites) a tenu.
- **Stratégie de remplacement mécanique + corrections pilotées par `tsc`** : remplacements bulk sûrs (`as any` supprimé, `: any[]` → `: unknown[]`, `Promise<any>` → `Promise<T>`), puis itération `tsc` pour poser les bons types aux bons endroits. Beaucoup plus rapide que site par site.
- **Mocks de tests en `jest.Mock` lâches** (`x as unknown as jest.Mock`, ou mapped type `{ [K in keyof T]: jest.Mock }`) plutôt qu'en `as any` : `mockReturnValue`/`mockResolvedValue` acceptent alors les fixtures partielles (`{ data: … }` sans enveloppe AxiosResponse complète) sans aucun cast.
- **Fixtures complétées plutôt que castées** quand le type est simple (`AgentInstance.isMinimized/isMaximized`, `PendingNodeAttachment.id/origin/createdAt`, `RobotId.Archi` à la place de `'archi'`) : plus honnête, et ça a révélé une attente à corriger documentée (lot 14).
- **Gate hygiène bloquant** : `hygiene-ratchet` + `format:changed` + eslint errors exécutés localement avant chaque commit → zéro surprise en CI. Le ratchet compte aussi les **commentaires** (regex bête sur le contenu) : ne jamais écrire le motif `as any` / `any[]` dans un commentaire.

## Pièges rencontrés (à ne pas reproduire)

1. **Supprimer `as any` aveuglément casse les mocks typés** : `jest.MockedFunction<typeof useAuth>` exige un `AuthContextType` complet ; `jest.spyOn(apiClient,'delete').mockResolvedValue({})` exige une `AxiosResponse` complète. Toujours remplacer par un cast vers le type cible (`as unknown as T`) ou rendre le mock lâche — ne pas juste effacer le cast.
2. **Fichiers CRLF** : `String.replace` avec des motifs `\n` échoue silencieusement sur du CRLF. Utiliser un helper qui essaie les deux variantes (`str.split('\n').join('\r\n')`), ou l'outil `edit`.
3. **`node` sur Windows n'accepte pas les chemins `/c/...`** dans `fs.readFileSync` — utiliser `C:/...` (slashes avant OK) ou `process.env` pour la racine dans les scripts temporaires.
4. **`package.json` en `"type": "module"`** → scripts temporaires en `.cjs` ; `write_file` matérialise les `\n` littéraux → dans les scripts générés utiliser `String.fromCharCode(10)` ; bash mange les backticks dans `node -e` → passer par des fichiers script.
5. **Ratchet = regex bête** : `Record<string, any>` et `<T = any>` ne sont PAS comptés, mais `any[]` dans un commentaire OUI. Ne pas "optimiser" en laissant traîner ces motifs.
6. **`git commit` sur working tree CRLF** : warnings « LF will be replaced by CRLF » bénins (les blobs commités sont LF) — `prettier --write` avant commit suffit.
7. **Un typage trop étroit casse silencieusement un flux legacy** : d'où `tsc 0` + suites jest des modules + full `npm test -- --runInBand` en final (95 suites / 589 tests PASS) à chaque jalon, jamais unilatéralement.

- Avant chaque commit : `tsc --noEmit` 0, `eslint . --quiet` 0, `node scripts/ci/hygiene-ratchet.mjs` exit 0 (baisse stricte), `prettier --write` puis `GITHUB_BASE_REF=main npm run format:changed` exit 0, `audit:workflow-architecture:strict` OK.
- Ne jamais affaiblir un test pour passer ; ne jamais recaler la baseline à la hausse (`hygiene:update-baseline` uniquement après baisse constatée — fait ici 376 → 0).
- Jamais de `any` déguisé : `unknown` + type-guards, ou casts structuraux explicites (`as unknown as T`) documentés ; contrats nommés aux frontières.
